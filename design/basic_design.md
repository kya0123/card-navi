## 1. 目的とスコープ

### 1.1 目的
店舗名を入力すると、保有カードと支払い方法の組み合わせのうち **年間で最もお得な決済経路** を即座に提示する。あわせて、ポイント払いにすべき場面を提示する。
店舗は名前で探すほか、**現在地の近くにある店舗の一覧からタップして選ぶ**こともできる（F13）。

### 1.2 スコープ

| 区分 | 対象 | 対象外 |
|---|---|---|
| 評価要素 | 通常還元率、店舗特約還元率、年間達成ボーナス（年会費優遇を含む）、年会費（見直すタブの損得計算のみ） | キャンペーン、期間限定ポイント、付与上限。マイルは1マイル＝1円で評価し、特典航空券などでの価値の上振れは考えない |
| 入力 | 店舗名（またはカテゴリ）、現在地（F13の利用時のみ・保存しない）、ボーナス目標設定、累計利用額（任意・概算） | 利用明細の取込、カード番号（下4桁も含む）、位置の常時追跡・移動履歴 |
| 出力 | 推奨カード＋支払い方法、候補上位3件、ポイント払い推奨の有無、持っていないカードの提案（任意・OFF可） | 家計簿、利用履歴分析 |
| 利用者 | 本人 | 家族カード、複数ユーザ |

### 1.3 対象マスタ
- **カード（22枚）**：初期5枚（三井住友カード ゴールド（NL）、楽天カード、ANAワイドゴールド（VISA）、三菱UFJカード、PayPayカード ゴールド）に、世間一般で使われている定番カードとポイ活でお得とされるカード（ポイ活向け。旧称：マニア推奨）を追加（三井住友カード（NL）、Olive、プラチナプリファード、Amazon Mastercard、PayPayカード、イオンカードセレクト、dカード、dカード GOLD、au PAY カード、JCB CARD W、セブンカード・プラス、エポスカード、エポスゴールド、リクルートカード、Marriott Bonvoy アメックス（通常・プレミアム）、ビューカード スタンダード）。利用者はこの中から保有カードを選ぶ
- **カードの収録基準（v1.13・未実装）**：カードをシリーズ（例：ANAカード、楽天カード）とランク（一般・ゴールド・プラチナ）で整理する。シリーズを収録したら、ゴールドが発行されている限り一般とゴールドを揃える（発行されていないシリーズは一般だけ）。プラチナはポイント率か年間ボーナスに差があるものだけ。国際ブランドの違いは、還元ルールが同じなら1枚の属性として扱う。第1弾で約19枚を追加し、約41枚にする（詳細設計32.3。楽天プレミアムカードは楽天カードと率が同じため収録しない）。第2弾で、収録済みシリーズの上位カード（Olive プラチナプリファード、ソラチカカード、エポスプラチナ、三菱UFJカード プラチナ・アメックス、JCBプラチナ）とローソンPontaプラスを追加し、約47枚にする。一覧にないカードは「その他のカード」として利用者が登録できる（F14）
- **決済手段**：カード物理/タッチ決済、Apple Pay・Google Pay等のスマホ決済、iD等、PayPay、モバイルSuica（JR東日本の乗車のみ。Suicaでの買い物は対象外）。チャージ元カードのポイントは、付与のあるビューカードのみ評価する（一般のカードはモバイルSuicaへのチャージにポイントが付かない）。v1.13で、単独で使うコード決済・電子マネー（d払い残高・楽天ペイ・au PAY・WAON・nanaco・楽天Edy）を追加予定。銀行口座・現金からのチャージを前提に、その支払い自体のポイントだけで評価する。現金はポイントが付かないため比べる対象にせず、現金しか使えない店に「現金のみ」と注記する（詳細設計32.11）
- **ポイント**：Vポイント、楽天ポイント、三菱UFJポイント（＝グローバルポイント、1pt＝5円相当）、ANAマイル移行用ポイント（1pt＝1円で評価）、PayPayポイント、JRE POINT、WAON POINT、dポイント、Pontaポイント、J-POINT、nanacoポイント、エポスポイント、Amazonポイント、リクルートポイント（いずれも1pt＝1円）、Marriott Bonvoyポイント（ホテル宿泊に使う前提で1pt＝1円）。v1.13で追加予定：ANAマイル・JALマイル（1マイル＝1円。ANAマイル移行用ポイントは廃止し、ANAカードはマイル数で持つ）、永久不滅ポイント（1pt＝5円）、メンバーシップ・リワード（1pt＝0.3円）
- **店舗カテゴリ**：コンビニ、スーパー、ドラッグストア、飲食チェーン、カフェ、EC、交通
- **件数**（ルール版 2026.09.24-2）：カード21・支払い方法7・決済経路91・店舗103・特約375。三井住友・三菱UFJの7%対象チェーンは公式ページから全件反映

## 3. システム構成

```
[PWA (ブラウザ / ホーム画面追加)]
 ├─ UI層（画面・入力）
 ├─ 推奨エンジン（純粋関数・UI非依存）
 ├─ リポジトリ層
 │   ├─ ルールマスタ（同梱の静的JSON・読み取り専用）
 │   └─ ユーザ設定（IndexedDB）
 └─ Service Worker（全資産をprecache → 完全オフライン）
        ┆ 近くのお店（F13）を使うときのみ。設定で選んだ一方にだけ問い合わせる
        ▼
[OpenStreetMap Overpass API（公開インスタンス）] または [Yahoo!ローカルサーチAPI（YOLP）]
```

- **技術スタック（実装）**：TypeScript、esbuild、自作の小さなJSXランタイム、手書きのService Worker、IndexedDB（自作ラッパー）、node:test（単体・ゴールデン）、Playwright（E2E・オフライン試験）。開発環境からnpmレジストリに接続できなかったため、当初案（Vite・Preact・vite-plugin-pwa・idb・Vitest）から変更
- **サーバ**：なし。静的ホスティング（GitHub Pages等）で配信のみ。公開用ファイルはフォルダなしの7ファイル（index.html、sw.js、manifest、アイコン4つ）
- **プレビュー版**：claude.ai 上のページ（Service Workerとファイル書き出しを無効にしたビルド）
- **マスタの更新**：Claudeが公開情報を再収集 → 差分をレビュー → JSON更新 → 再デプロイ → Service Workerが更新を検知し、次回起動時に反映
- **オフライン**：初回アクセス後はネットワークなしで全機能が動作すること（F13を除く）。CDNは使わない
- **外部API**：F13 でのみ、設定で選んだ検索先（OpenStreetMap の Overpass API、または Yahoo!ローカルサーチAPI）に周辺店舗を問い合わせる。応答は Service Worker でキャッシュしない。Overpass はAPIキー・利用者登録が不要、YOLP は利用者自身が取得したアプリIDが必要

### 4.2 推奨ロジック（F02）

**(1) 候補経路の抽出**
保有カードかつ有効な支払い方法の経路のうち、店舗で使えるもの（`acceptedRoutes`）。店舗が見つからない場合はカテゴリの既定値を使う。

**(2) 還元率の決定（優先順）**
1. 店舗×経路の特約ルール
2. カテゴリ×経路の特約ルール
3. 経路の通常還元率

**(3) 実質還元率**

```
実質還元率 = 還元率 + ボーナス換算率

ボーナス換算率 = ボーナス価値 ÷ 達成条件額
   以下をすべて満たす場合のみ加算、それ以外は0:
   ・ユーザが「狙う」をON
   ・未達成（概算累計 < 達成条件額）
   ・期限内（今日 ≤ 期限）
   ・その経路の支払いが達成条件の対象（countsTowardBonus = true）
```

- **ボーナス価値**：マスタに円換算額で保持する（例：年会費が永年無料になる場合はその年会費額、ボーナスポイントは1pt＝1円）
- **考え方**：達成条件額を使い切ったときに、ボーナスが1円あたりいくらに相当するかを上乗せする近似。未達成で終わった場合は損になりうるため、画面に「達成見込み」を表示して判断材料にする

**(4) 並べ替え**
実質還元率の降順 → 同率なら「ボーナス対象の経路」を優先 → さらに同率ならユーザ設定の優先順。
同じカードで実質還元率が同じ経路は1件にまとめ、使える支払い方法を列挙する（詳細設計 D1）。

**(5) 付与単位と端数**
金額が入力された場合のみ、付与単位（例：200円ごと）と端数処理（切り捨て等）で獲得ポイントを計算して表示する。金額の入力は任意で、未入力なら還元率のみで比較する。

**(6) 比較範囲（v1.11）**
- 結果の上で「持っているカード｜登録カード（N枚。Nはマスタのカード枚数で、その他のカードは含めない）」を切り替える。既定は「持っているカード」（(1)のとおり）。保有カードが0枚のときは登録カード全体で推奨し、切り替えは出さない
- 登録カード表示では、持っていないカードの経路（使える支払い方法すべて）も候補に加える。同率なら持っているカードを先にする
- 各カードに「保有」「未保有」の印を付け、未保有カードには公式サイトへのリンク（アフィリエイトなら「PR」表記）を出す。結果の下に「アプリに登録している主なカードN枚の中での比較です。日本のすべてのカードではありません」と注記する
- ボーナスの加算とポイント払いの判定（F03）は、持っているカードだけで行う。未保有カードの提案ヒント（F08）は出さない
- 登録カード表示では、同じシリーズで実質還元率が同じカードを1枠にまとめ、「楽天ゴールドカードも同じポイント率」のように添える。代表は持っているカード→年会費の安いカードの順で選ぶ（v1.13。持っていないカードにはボーナスを加算しないため、同じシリーズの一般とゴールドが同率で上位を占めるのを防ぐ。詳細設計32.7）

### 4.3 年間ボーナス目標（F05）

| 項目 | 型 | 説明 |
|---|---|---|
| 狙う | チェックボックス | ONのときのみ推奨ロジックに反映 |
| 達成条件額 | 円 | マスタの値を初期値とし、編集可能 |
| 入会年月 | 年月 | カードの入会年月。期限計算の起点（カード番号・入会日は保持しない） |
| 期限 | 日付 | 入会年月から自動計算（4.3.1）。規約の例外に備えて手動で上書き可能 |
| 概算累計 | 円（任意） | ユーザが月1回程度の粗い粒度で更新する。「達成済み」チェックでも代用可 |
| 最終更新日 | 日付 | 自動記録 |

#### 4.3.1 期間と期限の計算

期間の種類はマスタでボーナスごとに持つ。

| 種類 | 期間 | 例 |
|---|---|---|
| 入会月基準（既定） | 下記の計算 | 三井住友ゴールド（NL）、エポスゴールドなど |
| 入会月基準・初年度は別 | 入会月から指定の月数（例：13か月）は初年度として別の期間・特典額。以後は入会月基準 | PayPayカード ゴールド（初年度13か月・6,000pt、2年目以降12か月・11,000pt） |
| 毎年同じ月日から | 毎年の指定日から翌年の前日まで。入会年月は使わない | dカード GOLD（12月16日〜翌年12月15日） |

入会月基準の計算：

```
期間開始月 = 入会月 + startOffsetMonths（マスタ値。0 or 1）の、今日を含む直近の年度
期間       = 期間開始月の1日 〜 12か月後の前月末日
期限       = 期間の末日
例) 入会 2024年4月、offset=0 → 今日 2026-09-22 の期間は 2026-04-01〜2027-03-31、期限 2027-03-31
```

- 期限を過ぎたら次の期間へ自動で繰り越し、概算累計と達成済みフラグをリセットする（リセット前の値は「前期実績」として1件だけ保持）
- 期限を手動で上書きした場合は自動繰り越しの対象外とし、期限切れ時に更新を促す

**表示内容**：進捗率、残額、残日数、**必要な月額（残額÷残月数）**、状態（進行中／達成済み／期限切れ）。
**期限を過ぎた場合**：4.3.1に従い次の期間へ自動で繰り越す。繰り越した旨を1回だけ通知する。

### 4.4 ポイント払い推奨（F03）

```
推奨1位の経路の還元率 ≤ その経路の通常還元率（＝特約なし）
  かつ その店舗で使えるポイント（usablePoints）がある
  かつ ボーナス加算がない（狙っているボーナスの対象外、または未設定）
→ 「ポイント払いがおすすめ（〇〇ポイント）」と表示
```

- 期間限定ポイント、ポイント残高、ポイント払い時にポイントが付くかどうかは考慮しない
- 条件の3つめは、ボーナス達成を目指している最中にポイント払いで累計が進まなくなるのを防ぐため

### 4.5 カード提案（F08〜F10）

収益化設計書（案）に基づく機能。詳細は `design/detailed_design_card_suggest.md`。

- **役割分担**：おすすめタブ（S01）は「このお店でどのカードを使うか」を示す。ヒント（F08）とバナー（F10）はおすすめタブに残す。年会費を回収できるかの計算は見直すタブ（S07）で行う
- **比較方法**：ボーナス加算なしの設定で、現在の1位の率と、候補カードを1枚追加したときの1位の率を比べる。最近使ったお店をもとに「上がるお店の数」「率の変化」「1万円あたりの増加額」を示す
- **候補カード**：マスタにあり保有していないカード。その他のカード（F14）は候補にしない

#### 4.5.1 年会費の回収計算（F09・見直すタブ）

- **入力**：月のカード利用額（既定5万円。見直すタブで変更でき、端末に保存）。よく行くお店に均等に使う前提の目安とする。提案カードか年会費のある保有カードがあるときだけ、「月5万円のカード利用で計算しています［変更］」の1行で表示し、［変更］で入力欄を開く
- **年間の損得** = 還元の増加 ＋ ボーナス − 年会費
  - 還元の増加 = 月の利用額 × 12 × 上がるお店の割合 × 率の差の平均
  - ボーナス = そのカードに移る利用額（年）が達成条件額以上なら特典額（2年目以降の額）
- **回収ライン** = 年間の損得が0円になる月の利用額（100円切り上げ）
- **追加すると得なカード**：年間の損得の大きい順に並べる。年会費を回収できないカードは「この使い方では年会費を回収できません」の見出しの下にまとめる
- **持っているカードの年会費**：年会費のかかる保有カードごとに、そのカードがなかった場合と比べた年間の上乗せ（＋ボーナス）と年会費を比べ、回収できているかを表示する
- **ヒント・バナーとの関係**：バナー（F10）は、年間の損得がプラスのカードがあるときだけ出す。並び順・判定は計算結果だけで決め、アフィリエイトの有無は影響させない
- **表示の頻度**：初回起動から14日間は出さない。最初は7日ごと、反応がなければ7→14→30日に広げ、タップで7日に戻す。内容が変わったら7日で出す。×で閉じたら60日出さない。同じ日にヒントとバナーの両方は出さない
- **中立性**：並び順は計算結果のみで決め、アフィリエイトの有無は影響させない。アフィリエイトリンクには「PR」を表示し、なければ公式サイトへリンクする。リンク先一覧（`affiliates.json`）は公開まで空
- **広告の方針**：画面（S09）で方針を明示する

### 4.6 近くのお店から選ぶ（F13）

**(1) 利用の流れ**

```
ホーム（S01）の「近くのお店」ボタン
 → 初回のみ説明（現在地を外部に送ること）に同意
 → 現在地を取得 → 選んだ検索先に半径内の店舗を問い合わせ
 → マスタの店舗に紐付くものを距離順に一覧表示（S10）
 → タップ → F02 の推奨結果（S01）。「最近使った店」にも追加
```

操作は「起動 → 近くのお店 → 店舗をタップ」の2タップ。

**(2) 位置情報の取得**
- ブラウザの位置情報APIを使い、ボタンを押したときに1回だけ取得する（常時追跡しない）
- 高精度を要求し、タイムアウトは10秒。1分以内に取得した位置があればそれを使う
- 精度が100mより粗いときは「位置の精度が低いため、近くのお店が正しく出ないことがあります」と注記する

**(3) 検索先の選択**

設定で次のどちらか一方を選ぶ。検索先ごとの処理は差し替え可能な部品（検索先アダプタ）に分け、後から検索先を追加できるようにする。

| 項目 | OpenStreetMap（Overpass API） | Yahoo!ローカルサーチAPI（YOLP） |
|---|---|---|
| データ | OpenStreetMap（有志の登録データ） | 全国の電話帳データ・店舗オーナーの投稿 |
| 日本の店舗の網羅性 | チェーン店は多いが地域により漏れ | 高い |
| 事前準備 | 不要 | 利用者が Yahoo!デベロッパーネットワークでアプリIDを取得し、設定画面に入力 |
| 無料の範囲 | 公開インスタンスの利用方針の範囲（目安1日1万回） | 1アプリ1日5万回。商用利用は有償版 |
| 紐付け | ブランド識別子 → 店名 | 店名のみ |
| 出典表示 | © OpenStreetMap contributors | YOLPのガイドラインに従ったクレジット表示 |

- **既定は OpenStreetMap**（準備なしで使えるため）。YOLP はアプリIDを入力したときだけ選べる
- 選んだ検索先が失敗しても、もう一方へ自動では切り替えない（同意していない相手に位置を送らないため）

**(4) 周辺店舗の取得（共通）**
- 現在地を中心とした半径内の店舗・飲食店を問い合わせる。Overpass の接続先は設定値として持ち、既定は overpass-api.de。YOLP は距離順で取得し、業種で店舗・飲食店に絞る
- 半径は既定300m、設定で100／300／500／1000mから選ぶ
- 送る座標は小数点以下4桁（約10m）に丸める
- 前回の問い合わせから5分以内かつ50m以内の移動で、検索先・半径が同じなら、前回の結果を使う（負荷と回数を抑えるため。結果はメモリ上のみで保存しない）
- タイムアウトは10秒。利用は手動操作のときだけなので、どちらの検索先でも無料の範囲に収まる

**(5) マスタの店舗との紐付け**
- 対象はEC・交通・自販機を除く実店舗（現行マスタで98店舗）
- 紐付けの優先順は ①ブランド識別子の一致（OpenStreetMapのみ。マスタの店舗に Wikidata ID を追加する） ②ブランド名・店名がマスタの店名／別名と一致（表記ゆれは F01 と同じ正規化で吸収。「セブン-イレブン 辻堂駅前店」のように支店名が続く場合は、最も長く一致した店舗を採用）
- 検索先によらず、紐付けと一覧表示は同じ処理で行う
- 紐付かない店舗（個人店・マスタにないチェーン）は一覧に出さない。マスタにない店は還元ルールがなく推奨できないため。一覧の下に「一覧にないお店は、名前で探す／カテゴリから選ぶ」への導線を置く

**(6) 表示（S10）**
- 距離の近い順に最大20件。店名（支店名があれば併記）、距離（「約120m」）、高還元ラベル（S02 と同じ。例「三井住友 7%」）
- 同じチェーンの別の店が複数あれば、それぞれ表示する（どれを選んでも推奨は同じ）
- 一覧の下に、使った検索先の出典を表示する

**(7) 異常時の動作**

| 状況 | 表示と動作 |
|---|---|
| オフライン | 「近くのお店はネット接続が必要です」。名前で探す・カテゴリへの導線を出す |
| YOLPを選んでいるがアプリIDが未入力・無効 | 設定画面への導線を出す |
| 位置情報の利用を許可していない | 端末・ブラウザの設定で許可する方法を案内し、名前で探す導線を出す |
| 位置の取得・問い合わせがタイムアウト、サーバが混雑（エラー応答） | 「取得できませんでした」と再試行ボタン |
| 該当0件 | 半径を広げるボタンと、名前で探す・カテゴリへの導線 |

いずれの場合も、他の機能には影響させない。

**(8) プライバシーとライセンス**
- 検索先ごとに、初回利用時に「現在地を〇〇（OpenStreetMap／Yahoo! JAPAN）のサーバに送って近くのお店を探します。アプリは位置を保存しません」と説明し、同意を得てから使う。検索先を切り替えたら、その検索先について改めて同意を得る。同意したことだけを保存する
- 座標と取得した店舗一覧は保存しない（IndexedDB・バックアップに含めない）
- 出典は一覧と設定画面に表示する。OpenStreetMap のデータは ODbL ライセンス。YOLP はガイドラインのクレジット表示に従う
- YOLP のアプリIDは端末内（IndexedDB）にだけ保存し、公開するファイル（GitHub Pages）には含めない。バックアップにも含めず、端末を移したら入力し直す
- 設定で F13 をOFFにできる（OFFで「近くのお店」ボタンを表示しない）

## 5. データ設計

### 5.1 ルールマスタ（静的JSON・読み取り専用）

```jsonc
{
  "schemaVersion": 1,
  "masterVersion": "2026.09.24-1",
  "series":   [{ "id", "name", "kana", "aliases": [] }],   // v1.13：カードのシリーズ
  "cards":    [{ "id", "name", "brand", "pointId", "annualFee", "officialUrl",
                 "series", "tier": "general|gold|platinum" }],
  "methods":  [{ "id", "name", "type": "card|tap|wallet|code|transit|emoney" }],   // emoney は v1.13
  "points":   [{ "id", "name", "yenPerPoint", "usableScope": "visaMerchants|paypayMerchants|suicaMerchants|listed|none" }],
  "routes":   [{ "id", "cardId|null", "methodId", "pointId", "baseRate", "unitYen", "pointsPerUnit",
                 "unitScope": "perTransaction|monthlyTotal", "rounding": "floor",
                 "countsTowardBonus": true, "sourceUrl", "checkedAt", "confidence", "needsReview", "note",
                 "defaultEnabled", "label" }],   // v1.13：カード以外の経路で、新規利用者に最初から有効にするもの／チェックボックスの表示名
  "bonuses":  [{ "id", "cardId", "thresholdYen", "valueYen", "oneTimeValueYen", "periodType": "joinMonth",
                 "startOffsetMonths": 0, "excludedMethods": [], "description" }],
  "categories":[{ "id", "name", "defaultMethods": [] }],
  "stores":   [{ "id", "name", "kana", "aliases": [], "categoryId",
                 "acceptedMethods": [], "usablePoints": [],
                 "osmBrandWikidata": [],      // F13用（任意）。OSMのブランド識別子
                 "cashOnly" }],               // v1.13：現金のみの店（acceptedMethods は空）
  "rateRules":[{ "id", "target": { "storeId|categoryId" }, "routeId", "rate",
                 "validFrom", "validTo", "sourceUrl", "checkedAt", "conditions" }]
}
```

- 率はすべて小数で持つ（例：0.5% → 0.005）。`baseRate` は円換算の還元率で、`pointsPerUnit × yenPerPoint ÷ unitYen` と一致すること（マスタ検証で確認）
- `acceptedMethods` を省略した店舗はカテゴリの `defaultMethods` を使う。候補経路は「保有カードの経路のうち、支払い方法が店舗で使えるもの」
- `unitScope = monthlyTotal`（月間合計で付与単位を計算するカード）は、1回の支払いでは端数処理せず還元率で評価する
- `oneTimeValueYen`（初回達成時のみの価値。例：年会費永年無料）は、ユーザ設定で「達成済み」でなければボーナス価値に加算する
- ポイント払い推奨で使えるポイントは、店舗の `usablePoints` と、`usableScope` が店舗の受入決済に合うポイント（例：VポイントはVisaタッチ/オンラインが使える店）の和
- `confidence`（high/medium/low）と `needsReview` を画面の「マスタ情報」に表示する
- `checkedAt` から180日を過ぎたルールは「要確認」として警告を表示（日数は設定で変更可）
- キャンペーンは登録しない。登録基準は、常設の特約で公式ページに記載されているもののみ
- `osmBrandWikidata` は、ルールと同じくClaudeが公開情報（OpenStreetMap・Wikidata）から収集してマスタ更新時に反映する。未設定の店舗は店名の一致だけで紐付ける

### 5.2 ユーザ設定（IndexedDB）

| ストア | 主な項目 |
|---|---|
| ownedCards | cardId、入会年月、有効な支払い方法、優先順 |
| bonusGoals | bonusId、狙う、達成条件額、期限、期限の手動上書き有無、概算累計、達成済み、前期実績、最終更新日 |
| recentStores | storeId、最終利用日時（最大20件） |
| settings | その他のカード（名前・ポイント・基本のポイント率、最大5枚。v1.13）、警告日数、エクスポート日時、カード提案の表示ON/OFF、配色、近くのお店のON/OFF・検索先・検索半径・検索先ごとの同意日時、YOLPのアプリID（バックアップ対象外）、schemaVersion |
| meta | 提案の表示記録（初回起動日、最終表示日、表示間隔、×で閉じた期限など） |

- **保持しない情報**：カード番号（下4桁も含む）、利用明細、個人名、位置情報（座標・周辺店舗の取得結果）
- 起動時に `navigator.storage.persist()` で永続化を要求する
- 最終エクスポートから30日を過ぎたらバックアップを促す

**タブ**：おすすめ／カード／ボーナス／見直す／還元情報／設定 の6つ（S02・S09・S10 はタブ外）。

**デザイン**：デジタル庁デザインシステムを参考にする。フォントは同梱せず端末標準、ライトテーマのみ。配色は5案から選択（既定ネイビー×ゴールド。状態色・フォーカスは共通）。政府のロゴ・名称は使わず、出典と無関係である旨を記載。文字と背景のコントラスト比は4.5:1以上

**操作目標**：起動 → 店舗入力 → 結果表示まで3タップ以内。結果は入力から1秒以内に表示。近くのお店は「起動 → 近くのお店 → 店舗をタップ」の2タップで、一覧は通常3秒以内（通信込み）に表示。

## 7. 非機能要件

| 区分 | 要件 |
|---|---|
| オフライン | 初回アクセス後は機内モードで全機能が動作（F13を除く。F13はオフラインである旨を表示し、名前で探す・カテゴリへ誘導） |
| 性能 | 推奨計算100ms以内、初回表示2秒以内（オフライン時）。F13の一覧表示は通常3秒以内（位置取得・問い合わせのタイムアウトは各10秒） |
| 対応環境 | iOS Safari（ホーム画面追加）、Android Chrome の最新2バージョン。位置情報APIのためHTTPSで配信する（GitHub Pagesは対応済み） |
| セキュリティ | 外部通信は更新確認とF13の問い合わせ（選んだ検索先のみ）のみ。個人を特定できる情報やカード番号は保持しない |
| プライバシー | 位置情報はF13のボタン操作時だけ取得し、丸めた座標を選んだ検索先への問い合わせにのみ使う。座標・取得結果は保存しない。検索先ごとに初回に外部送信の説明と同意。YOLPのアプリIDは公開ファイルに含めない |
| 保守性 | 推奨エンジンは純粋関数として分離し、UIなしでテスト可能にする |
| 免責 | 推奨は参考情報であり、実際の還元は各社の規約によることを明示 |
